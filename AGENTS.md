# Правила редактора офферов

- Adrobot хранит черновик настроек офферов в PostgreSQL через SQLAlchemy.
  Keitaro хранит опубликованную конфигурацию потока. Кнопка «Применить»
  отправляет в Keitaro итоговый список активных офферов с их долями.
  При ошибке публикации черновик сохраняется.
- При повторной загрузке из Keitaro сохраняй локальные правки. Если ранее
  сохранённый оффер исчез из потока, сохрани его строку в черновике и покажи
  статус `Removed`. Храни ID оффера и его последнюю известную долю, чтобы
  пользователь мог восстановить привязку и опубликовать её повторно.
- Восстановление привязки по ID возможно, пока сам оффер существует в Keitaro.
  После подтверждения синхронизации удали строки `Removed` из черновика.
  При отказе или конфликте сохрани неподтверждённые строки для восстановления.
- Для каждого оффера черновика сохраняй долю и признак закрепления.
  При изменении набора активных офферов доли закреплённых остаются фиксированными.
- Вычти сумму долей активных закреплённых офферов из 100% и раздели остаток
  поровну между активными незакреплёнными офферами. Офферы со статусом
  `Removed` не участвуют в расчёте и публикации.
- Например, при закреплённой доле 40% два активных незакреплённых оффера
  получают по 30%. Если один из них убрать, другой получает 60%.

# Визуальные правила Adrobot

- Перед изменением интерфейса прочитай текущий шаблон и подключённые правила
  из `adrobot/static/css/application.css`. За образец бери соседний блок
  на той же странице или ближайший аналог в существующем интерфейсе.
- Добавляй действие к существующей группе того же назначения. Действия
  кампании размещай в `.campaign-actions` и используй `.pressable--action`.
  Переключатель использует собственный `.switchable` и общий токен
  `--action-min-block-size`. Для удаления используй
  `.pressable--destructive`, для пары «иконка + подпись» —
  `.pressable__content` и маски Phosphor из `icons.css`.
- Базовый вертикальный отступ `--space-v` задаётся через `clamp()`,
  горизонтальный `--space-h` равен удвоенному `--space-v`. Высоту кнопок
  выводи из этой шкалы. На сенсорных устройствах учитывай `--coarse-target`.
- Используй существующие шаблоны, классы и токены отступов, цвета и размеров.
  Если работа касается одного элемента, ограничивай изменение этим элементом
  и его композицией. Меняй общий компонент только при задаче на сам компонент.
- Пользовательский интерфейс сообщает, что произошло и что можно сделать
  дальше. Команды миграций, переменные окружения и детали диагностики
  размещай в README или в выводе для разработчика.
- После изменения интерфейса проверяй его в браузере в широком и узком
  контейнерах. Сравни высоту, порядок, выравнивание и перенос элементов с
  соседними. Для интерактивного элемента проверь затронутые состояния,
  например раскрытое, отключённое и фокус с клавиатуры. Если браузер
  недоступен, проверь разметку и применяемые CSS-правила и явно сообщи,
  что визуальная проверка осталась открытой. Pytest проверяет поведение
  сервера, визуальная проверка выполняется отдельно.
